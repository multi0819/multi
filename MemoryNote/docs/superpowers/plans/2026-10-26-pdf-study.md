# PDF study and capture implementation plan

Approved by the user's detailed design and request to modify. Goal: study PDFs inside MemoryNote with document-first screen and captured regions routed via 문제/지문/풀이; 문제 starts a new note, subsequent regions append to the selected current note. Preserve existing notes and 1.9.3 behavior.

Implementation boundaries: StudyPdfCanvas owns one rendered bitmap, normalized selection, zoom/pan and per-page atomic ink storage; PdfStudy owns import, metadata, background page rendering, compact UI, current-note routing, crop previews and original-page links. Add PDF import/recent button to existing editor. Hook a reserved activity result request and PDF-aware back handling. Use native PdfRenderer with bounded current-page bitmap, stream imports to private files; no bulk extraction, OCR or external API.

Note storage: use existing general Note schema and inline image markers. Role sections in body preserve question/statement/solution; solution crops have full-image masks for existing reveal flow. Keep separate durable document/segment metadata for source links and undo/move. Use copy-before-save and cleanup on write failure. Subject/chapter are inherited from the editor. Source PDF files/metadata live separately from existing crop-inclusive note backups.

Tasks:
1. Implement canvas + geometry/persistence tests (delegated; fixed Java interface).
2. Implement PdfStudy routing and editor entry; preserve result/back handlers for existing features. Persist page/current-note and capture source; support preview, undo last addition, move last role and original return.
3. Compile overlay on 1.9.3, test routing and geometry, verify actual DEX linkage/resource/signature/version and regressions. Independent review, fix important findings, deliver same-ID signed update.

Native device limitations must be disclosed; do not claim physical Samsung validation.
